## Drift Analysis

### Negative Drift (Practices Degraded)

#### 1. "Edge A is outside this audit's input scope" — load-bearing framing error
**What changed**: The skill's documented contract said the audit measured Edge B only and pointed at `terraform plan` as the Edge A check. In practice, no run actually composed `terraform plan` with `/tf-aws audit` — the bracketing turned the prescription into a permission to skip the check.

**Evidence**:
- 2026-04-30 audit reported `δ = 0` claim baseline despite the user's later observation that `.tf` ↔ `.tfstate` divergence had been silently accumulating.
- CI workflow `.github/workflows/terraform-test.yml` had `key="dev/terraform.tfstate"` (deprecating) since at least 2026-01 (predates the active git history we sampled). PR plans were producing phantom mass-CREATE diffs that bypassed the "run terraform plan" prescription because no human read the plan output carefully enough to notice it didn't match the expected ~24-resource scope.
- User correction 2026-04-30: "I think edge A is very much needed. assuming that Edge A is not needed is like assuming that every edit to .tf has instant .tfstate that match it."

**Old framing**: Edge A is BS-5 (a blind spot) with `terraform plan` as plug.

**New framing**: Edge A is in scope. Phase A.5 (HCL parse + address-level diff) catches structural disagreement. `terraform plan` remains the residual plug for field-level disagreement on non-fingerprinted fields.

**Why the old framing was attractive but wrong**: it kept the audit's input scope tidy (only `.tfstate` and AWS, two read sources). It transferred the cost to the user (run `terraform plan` separately). The transfer was structurally identical to "Doppler injects env vars at runtime; TF doesn't need to know" — both are excuses for an incomplete contract that work until the day they don't.

**Recommendation applied**: Phase A.5 added; BS-5 description rewritten to explain the framing change.

#### 2. Phase D's `delete-empty-shell` was unsafe for resources with peer references
**What changed**: The triage said "if r matches empty-shell pattern → verdict = delete-empty-shell." It didn't check whether other resources referenced `r`. The 2026-04-30 SG validation (`sg-03e0bb93ea6bd920e`: 0 ENIs but referenced by an out-of-scope SG's ingress rule) showed this would emit `aws ec2 delete-security-group ...` commands AWS would reject — or worse, succeed and silently break a peer.

**Evidence**:
- The user's manual dataflow check on `aws_security_group.line_bot_ticker_report` had to be done by hand to discover the referencing rule.
- 2026-04-28 audit didn't surface the relationship; the human caught it.

**Recommendation applied**: Phase B3.5 added (reverse-reference walk per type — SG, IAM role, S3 policy, KMS key, CloudFront OAI). Phase D updated so `delete-empty-shell` is only emitted when `incoming_refs` is empty or all dead. Phase D output extended with two-step delete commands when a non-trivial closure exists (T3.b).

#### 3. Lambda env drift always resolved to `review` — created human queue without progress
**What changed**: Phase D2's field-direction map said `aws_lambda_function.environment → review`. This was correct *in absence of context*. But the project always has context: the codebase reads (or doesn't read) every declared key. The default verdict of `review` punted every Lambda env drift item to a human, who then ran the same `grep` Phase D2 could have run.

**Evidence**:
- 2026-04-30 audit on `telegram_api`: 16 keys diff, all `review`. The human verification then took 30 minutes of manual grepping per Lambda. Phase D2 already had access to the source tree.
- Repeated across 4 Lambdas: telegram_api, line_bot, report_worker, ticker_scheduler.

**Recommendation applied**: T3.d codebase-aware drift inference. Per-key verdicts: `apply-tf` (used in code, not in Doppler set), `trim-spec` (used in code, in Doppler set OR not used at all), `refresh-tf` (in AWS, not declared, used in code), `review` (residual ambiguity). The human only sees what's still ambiguous.

### Positive Drift (Patterns the Skill Should Codify)

#### 4. Phase H self-test as the BS-6 plug
**What changed**: Implicit in the user's questioning — "you said you measured X; how do I know you actually measured X?" The audit's coverage numbers were claims, not assertions. The 2026-04-28 vs 2026-04-30 audit count comparisons revealed the skew (1 DRIFTED → 6 DRIFTED was not new drift; it was newly-measured drift).

**Recommendation applied**: BS-6 added to the Blind Spots section. Phase H coverage assertions added — every coverage claim gets a corresponding assertion that fails the audit (non-zero exit) if the underlying inputs didn't match expectations. Treat audit-execution skew as a hard stop, not a warning.

#### 5. Backend-reference sweep before mutating verbs
**What changed**: The 2026-04-30 CI regression (terraform-test.yml pointing at deprecating state) demonstrated that *reading* the wrong state file silently produces wrong plans. *Mutating* the wrong state file would have been catastrophic. There was no pre-flight check.

**Recommendation applied**: Phase F.5 — sweep `.github/workflows`, `justfile`, `scripts`, `terraform/envs`, `Makefile` for any `key=*.tfstate` reference. Cross-reference against `state.role`. Refuse `--apply` if any deprecating-keyed entry point exists. Override flag (`--allow-deprecating-backend`) is loud — documents intent in the apply log.

#### 6. `state.role` schema in replica config
**What changed**: The replica config had `x.primary` and `x.legacy` as separate fields. This implicitly encoded "primary is canonical, legacy is deprecating," but the audit had no way to read that intent — it just unioned both lists. Phase D's DOUBLE handling guessed "keep primary," but the guess was hard-coded in the algorithm, not declared in the config.

**Recommendation applied**: New schema `x.files: [{uri, role, reason}]` with `role ∈ {primary, deprecating, archived}`. The audit reads role explicitly. Phase F.5 uses it. Phase D uses it. Old fields kept for one cycle of compat.
