Read the diagram as: SFN keeps fanning out at full speed (46) — but instead of invoking workers directly, it just enqueues. The new SQS+ESM throttle is the throttle. The existing worker logic is reused unchanged inside a new wrapper Lambda. Aurora and Yahoo are both untouched in code; their traffic shape is what changes (smooth, paced, bounded — instead of bursty).

Why maximum_concurrency = 5

Of every value in the design, this is the only knob that differs from fund_data_sync's matching value (which is 10). That fact is itself the proof the abstraction is correct: everything else — TF module, handler shape, IAM, return contract, observability — transfers verbatim.

Instance Bottleneck Concurrency cap
fund_data_sync Aurora write throughput (RDS Proxy connection pool ≈ 10) 10
precompute_consumer (this design) Yahoo Finance per-IP rate limit (NAT shared egress) 5

Throttle math: 56 tickers ÷ 5 concurrent ≈ 12 batches × ~30 s each ≈ ~6 min total wall-clock, same order as today's run — but ending at 56/56 cached instead of 42/56, because failures redrive instead of disappear.

The DRY decision (reuse-by-abstraction)

Two levels of "DRY" were on the table — the design picks the looser coupling deliberately:

Option What's shared Coupling Verdict
Reuse the instance One queue + one Lambda for both fund-sync and precompute Tight. Throughput budgets collide. Blast radius merged. Different IAM needs forced into one role. ❌ Rejected.
Reuse the abstraction (this design) TF module, handler-shape idiom, IAM template, alarm template Loose. Domain-separated runtime. Knob differs (5 vs 10). Failure of one doesn't touch the other. ✅ Chosen.

Two concrete instances now exist. Per Rule of Three, the pattern hasn't yet earned promotion to a named kernel principle, but a .claude/patterns/throttled-pipeline.md doc is on the table as an optional artifact so the third instance can compose it without rediscovery.

Verification (Layer 1 → 4 per Principle #2)

LayerCheckPass criterion
1 — Surface terraform apply exit code; SFN execution status 0 / SUCCEEDED
2 — Content Manual aws sqs send-message → consumer logs ticker → Aurora row appears row present in precomputed_reports
3 — Observability CloudWatch logs /aws/lambda/dr-daily-report-precompute-consumer-dev show: start → ticker → Aurora write → 200 narrative complete; Yahoo throttles surface as retries, not silent drops
4 — Ground truth Morning after deploy: SELECT COUNT(*) FROM precomputed_reports WHERE report_date = CURDATE() 56/56; DLQ empty; oldest-message-age never exceeded 30 min

Out-of-scope today (deliberate)

  • Single-writer daily price cache (option #3 in the solutions framework) — bigger fix; the pipeline being built here is the substrate for it later.
  • Staging / prod rollout — defer until dev shows 56/56 for ≥ 3 mornings.
  • Promotion to a kernel principle — wait for a third instance (Rule of Three).
