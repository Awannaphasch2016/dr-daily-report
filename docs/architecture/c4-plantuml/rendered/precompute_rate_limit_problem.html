Problem brief · 2026-05-03 · scope: dev environment, daily 5 AM precompute pipeline

Problem statement

Every morning, dev's scheduled precompute completes and Step Functions reports SUCCEEDED. But Aurora's precomputed_reports table for today's date contains only 42 of the 56 active DR tickers. The 14 missing ones are different each day — a stochastic gap that goes unnoticed because the workflow's surface signal (Layer 1 status) is green.

How to read these together

  1. The component diagram shows that exactly one external dependency sits between every report-worker and a successful Aurora write: the Yahoo Finance API. There is no cache, no proxy, no rate-control between the 46 Lambda workers and Yahoo.
  2. The sequence diagram shows that the per-worker retry policy (3 attempts × 2 s, then a same-IP fallback) is consumed within ~10 s — far less than the time Yahoo's per-IP window resets. Once a worker exhausts retries, no row is written and the SFN Map state silently moves on.
  3. The two diagrams together explain the dev/prod gap: same code, but dev's NAT IP is more saturated (developers running ad-hoc tests + scheduled run + Slack-bot live queries), so dev hits Yahoo's per-IP ceiling more often.
